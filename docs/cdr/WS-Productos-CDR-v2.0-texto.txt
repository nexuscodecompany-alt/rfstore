1 Qué es
Servicio SOAP que devuelve el catálogo de productos publicados en cdrmedios.com , con precios, stock,
ficha técnica e imágenes.
Tiene un solo método: productos_con_galeria . Con ese método se resuelve toda la integración.
Existe un segundo servicio que consulta el stock de una lista puntual de códigos. No es el recomendado y no se
habilita por defecto. Si tu caso lo necesita, pedilo expresamente a CDR.

Protocolo
SOAP (rpc/encoded)

http://schema.example.com
Método

Credenciales
email  + token , los provee CDR
IMPORTANTE
El token  no es la contraseña con la que entrás a la web. Es una clave aparte, exclusiva del web service. Si
intentás usar tu contraseña de login, no va a funcionar.

4 Cómo usar el parámetro fecha
Es la parte que más problemas genera. Son tres reglas.
4.1 Primera llamada: fecha vieja
Poné una fecha anterior a la existencia del catálogo, por ejemplo 2015-01-01 00:00:00 . Eso trae todo.
4.2 Llamadas siguientes: la fecha de tu última llamada
Guardá el momento en que hiciste la consulta y usalo como fecha  la próxima vez. Así solo recibís lo que cambió.
10:00  →  fecha = 2015-01-01 00:00:00    (primera vez, trae todo)
10:05  →  fecha = 2026-09-01 10:00:00
10:10  →  fecha = 2026-09-01 10:05:00
SI REPETÍS EL FULL SYNC TE BLOQUEAN EL USUARIO
Pedir el catálogo entero una y otra vez genera una respuesta muy pesada, y el sistema tranca al usuario que
hace la consulta. La fecha incremental no es una recomendación de eficiencia: es una condición de uso.
4.3 Sincronizá al menos una vez por día — obligatorio
Un producto que se queda sin stock se sigue devolviendo solo durante 24 horas. Pasado ese plazo, el servicio deja
de enviarlo.

===== PAGE 3 =====
LA CONSECUENCIA ES SILENCIOSA
Si sincronizás cada dos días, nunca vas a ver el momento en que el stock pasó a cero. El producto
simplemente deja de aparecer en la respuesta, y como tu sistema solo actualiza lo que recibe, se queda con el
último stock conocido para siempre. Vas a estar publicando disponibilidad de algo que no existe.
No hay error, no hay aviso. Por eso: una sincronización diaria como mínimo. Si publicás stock en tiempo real,
conviene más seguido.

7 Ocho cosas que hay que saber sí o sí
Son las que rompen integraciones. Todas están medidas contra el servicio real.
7.1
habilitado : convertilo a número, no lo compares como texto
El valor es un decimal, y la forma exacta en que te llega depende de tu cliente SOAP: puede ser 1  / 0  como
número, o "1.0"  / "0.0"  como texto. Comparar con igualdad contra "1"  o contra 1  falla en uno de los dos
casos.

===== PAGE 7 =====
if ( floatval(['habilitado'] ?? 0) > 0 ) { /* publicado */ }
El servicio incluye productos con habilitado  en cero. Filtralos vos.
7.2 Hay claves que directamente no vienen
No todos los productos traen las 24 claves. Cuando un dato no está cargado, el servicio a veces omite la clave entera
en lugar de mandarla vacía.
Caso confirmado: los combos —los que tienen un +  en el código, como MON368+SOP120 — llegan sin marca , sin
webmarca  y sin garantia . No vienen en blanco: no están.
En PHP eso es un Undefined array key; en JavaScript, undefined . Accedé siempre con guarda:
= ['marca'] ?? '';      // PHP
const marca = p.marca ?? '';       // JavaScript
7.3
descripcion  es HTML, copete  y nombre  no
descripcion  trae etiquetas ( <p> , <br /> , <strong> , <a> ). Medido: 5.980 de 5.984 productos la traen con
HTML; ninguno en texto plano.
Si la escapás como texto, tus fichas van a mostrar las etiquetas a la vista. copete  y nombre , en cambio, son texto
plano y no hay que interpretarlos como HTML.
Ojo si lo mirás en el navegador: si volcás la respuesta en una página de prueba, el navegador interpreta las etiquetas
y vas a ver texto plano con saltos de línea. El campo sí trae HTML — se comprueba sobre el string crudo, no sobre lo
renderizado. Los enlaces <a href>  que traen algunas fichas también desaparecen a la vista.
7.4 El gtin  NO identifica al producto
Varios productos distintos comparten el mismo GTIN, porque las variantes lo heredan del original: la versión outlet, la
refurbished, la que viene con sistema operativo preinstalado.
El único identificador es codigo . Si cruzás por GTIN vas a mezclar productos con distinto precio y distintas
prestaciones.
7.5 La URL de las imágenes cambia según quién consulta
El campo img  incluye un identificador que varía entre usuarios del servicio. La misma foto del mismo producto
tiene URL distinta para cada cliente.
Por eso: para saber si una imagen cambió, comparás el md5 , no la URL. El md5  es del archivo y sí es estable.
7.6 Los tipos numéricos vienen mezclados
Algunos campos numéricos llegan como texto ( "92.00" , "18.9" ) y otros como número ( 159 ). No asumas el tipo:
convertí siempre de forma explícita antes de operar.

7.7
pvp  y pvpml  en cero significan «sin sugerido», no «gratis»
Solo el 8,6 % de los productos publicados tiene un precio sugerido cargado. Cuando llega 0 , no hay sugerido
definido — no lo publiques como precio.
Y no confundas los tres precios:

7.8
categoria  es una jerarquía, no una etiqueta
Los niveles vienen en un solo string separados por >> :
Audio Imagen >> Auriculares y Microfonos >> Inalámbricos
Si querés armar un árbol de navegación, partí por ese separador.

9 Errores
El servicio responde con HTTP 200 aunque haya fallado. El error viene dentro del string devuelto, en JSON:
{"ERROR":"USUARIO NO CONFIGURADO"}
Mensaje
Qué significa
USUARIO NO CONFIGURADO
El par email/token no está habilitado para este servicio. Contactá a CDR.
Parámetro incorrecto
Revisá el formato de fecha  ( YYYY-MM-DD HH:MM:SS ).
NO ALCANZA CON MIRAR EL CÓDIGO HTTP
Siempre validá el contenido de la respuesta antes de procesarla. Un HTTP 200 no garantiza que haya datos.
